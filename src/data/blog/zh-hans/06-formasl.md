在上一篇文章中，我们走到了“需要一种语言”这个结论。如果意义必须在查询、推理、决策、场景和执行过程中持续保持可识别，那么它就不能只依赖散落在代码、数据库、文档和配置中的约定。我们需要一种显式形式，用来声明我们希望变得可计算的世界、其中哪些区别是重要的，以及哪些操作能够作用于这些区别。这种形式就是 FormaSL。

FormaSL 是一种可计算语义规范语言。这并不是因为所有意义都可以被一种语言捕获，也不是因为世界中发生的一切都可以被还原成一份规范，而是因为我们决定进行计算表示的内容，必须获得一种足够显式的形式，使我们能够直接对它操作，而不让它的区别依赖实现中的隐含知识。语言声明结构、关系、限定信息和操作；规范建立这些声明必须遵守的契约；语义决定哪些区别具有实质意义；而可计算性则使这个世界不再只是文档。

因此，一个 `.fsl` 文件并不只是供某个程序执行的配置。它是契约所声明意义的权威来源。这里的限定不可缺少：某项内容出现在 `.fsl` 中，并不会因为这一点就变成关于现实的真值。一个主张仍然是主张，一项规范的形式化仍然区别于现实中的规范，而一个被表示的授权仍然依赖领域赋予它的制度权限。契约拥有的是语义权威，而不是关于整个世界的普遍权威。

理解这意味着什么，最直接的方法是从一个简单关系开始。当前语法允许声明类型，并指定参与者所占据的角色：

```fsl
module relations_demo {
    type Agent
    type Item
    type Context

    relation Assigned {
        role assignee: Agent
        role item: Item
        role context: Context
    }
}
```

代码很少，但它所包含的信息超过了“三个元素彼此相连”这一事实。Agent、Item 和 Context 属于这个领域的词汇；Assigned 标识一个关系；assignee、item 和 context 则说明每个参与者在关系中处于什么语义位置。如果两个参与者交换角色，我们改变的不只是数据出现的顺序，而是正在被声明的关系本身。

这个结构，是我们在谈到 FormaSL 之前就已经遇到的问题的一种语言表达。有些关系需要保持自身身份、多个参与者以及不可互换的角色；它们还可以被进一步限定、参与其他关系，并在各种转换中继续保持可识别。项目当前选择的逻辑表示是一个基于角色的类型化关联元图。这并不强制物理存储采用图数据库。元图属于逻辑契约；持久化和执行属于另一个问题。

“表示一个关系”与“针对这个关系提出主张”之间的区别，在 Claim 中表现得更加清楚。如果我们希望记录 Alice 拥有某个账户，也许只保留这个命题本身还不够。我们可能需要知道是谁提出了这个主张、它处于什么语境，以及应该在哪个时间点解释它。语言允许把这些内容显式表达出来：

```fsl
module claims_demo {
    type Agent
    type Account

    relation Owns {
        role owner: Agent
        role asset: Account
    }

    assert claim c1 : Owns(owner: $alice, asset: $acc1) {
        by : $registry
        under : $jurisdiction
        valid_at : $t0
    }
}
```

Owns 关系作为 Claim c1 的内容出现，但二者并不是同一件事。Claim 是一种可归属的主张：它拥有身份，并可以携带发出者、语境和时间角色等信息。记录 `$registry` 在 `$jurisdiction` 下、于 `$t0` 提出了某项主张，并不等于宣布这项内容是绝对真值。语言保留的正是内容、主张与真值之间的距离，而这个距离本身正是我们构建世界模型的原因之一。

这种区别不会停留在语法层面。在当前实现切片中已经验证的 Claim 生命周期里，Claim 的身份、内容、发出者、发出依据以及语义发生仍然保持分离。传达或使用一个 Claim，不会自动创建另一个 Claim。同样内容的一次新主张，可以拥有不同身份、不同发出者和不同历史。内容相等不会抹去不同主张行为之间的区别。

已经声明的世界同样可以被计算。例如，语言区分 Match 与 Infer。查询寻找满足特定模式的结构；推理则依据规则与前提推导后果。这项区别具有实质意义，因为一个被推导出的结果，并不会仅仅因为经过计算就变成可归属于某个主体的主张。如果某个主体之后选择把这个结果作为一个 Claim 接受，就会发生新的语义转换，同时产生相应归属。推理可以成为主张的输入，但没有必要伪装成主张。

当计算进入规范领域时，同样的纪律继续存在。当前语言区分 Validate、Admit、Authorize 和 Decide。它们并不是“应用一条规则”的四种说法。验证某些条件的符合性，不等于把某个对象准入一个受治理的领域；准入不会自动赋予权限；授权也不是决策本身。让这些区别直接出现在语言中，可以防止它们恰好在开始决定行为的地方消失。

这个原则贯穿 FormaSL 当前的整个表面。除了查询、分析、推理和转换之外，它还包含用于验证、准入、授权、决策、修订、场景、执行请求、观察、源演化和纳入的操作。拥有这些不同操作的意义不在于积累关键字，而在于让不同形式的计算在进入更大的计算链条之后，仍然能够被识别为不同形式的计算。

场景特别清楚地展示了这一点为什么重要。语言可以从一个被标识为参照的世界出发，并引入只属于特定假设语境的前提：

```fsl
module scenario_demo {
    type World
    content Basis

    scenario WhatIf($base: World) using Basis from $base {
        assume $stressor
    }
}
```

场景不需要改变它作为基础所采用的世界。它在自身语境中引入一个假设，使我们能够在该假设下进行计算。如果某个结果在实质上依赖这项假设，这种依赖就必须继续保持可恢复。丢弃场景不会追溯性地修改参照世界；要让一个结果从“假设”获得其他语义地位，需要一次显式转换。因此，假设与参照世界之间的区别不再只是抽象原则，而是在语言中拥有直接表达。

变化和历史也遵循类似原则。FormaSL 提供修订与源演化操作，是因为改变已经表示的内容，不应意味着把先前状态当作从未存在。一次修正可以改变现在有效的内容，而在历史仍然重要时继续允许重建过去的状态；一个来源可以演化，同时保留与它的转换实质相关的信息。修订与擦除仍然不是同一件事。

决策与执行之间的边界同样进入语言。FormaSL 可以分别表示决策、执行请求和之后的观察，而不要求把这三个时刻融合成一个行动。一个决策可以产生发送给外部机制的请求；该机制可以尝试产生某种效果；之后，关于运行结果的信息可以被观察并重新纳入表示。执行器不会仅仅因为完成行动就获得语义权威，而一个技术上的成功响应也不需要自动被视为“所有预期外部效果都已经发生”的证明。

这些区别体现了语义连续性在语言内部的作用。当“推导”这一限定具有意义时，一个推导结论必须继续能够被识别为推导结果；一个 Claim 必须保留让它仍然可识别为那个 Claim 的内容；假设不能悄无声息地失去自己对场景的依赖；修订不能抹去仍然必要的历史；决策也不能仅仅因为下一阶段能够消费它，就变成执行。语言并不要求一切信息永久保存，但要求具有实质语义意义的丢失与转换不能偶然发生。

这也阻止实现追溯性地决定系统的语义模型。编译器可以重组结构，索引可以改变访问方式，数据库可以用另一种方式存储关系，某个机制也可以采用新的执行策略。这些选择对性能或规模可能非常重要，但没有任何一个实现选择会因此获得权威，把 Claim 变成事实、把假设变成发生，或把计算结果变成制度决策，仅仅因为某种物理表示更加方便。

在作为本系列依据的仓库切片中，项目认为 FormaSL 在当前边界下已经作为语言完成。这个说法是有意受到限制的。它并不意味着语言永远不会发生变化，也不意味着所有可以想象的领域都已经被建模、任何应用可能需要的所有机制都已经实现，或整个生态系统已经完成。它的意思是：相对于当前已经建立的语义边界，项目认为这一阶段语言核心所要求的基本区别集合已经闭合。

这个条件可以防止每一种新的计算需求都自动变成新的语言原语。某个应用可能需要一种存储机制、一个算法、一种机器学习模型或一套执行基础设施，而这种需要并不必然暴露语言语义中的缺口。对于 FormaSL 而言，问题是：是否存在一种需要被声明或保存的区别。至于由哪个机制执行某种具体计算，则属于另一个层级的问题。

当我们观察语言能够规定的各种操作时，这条边界会变得无法回避。一次推理可能需要专门的推理机制；一次分析可能需要统计模型；某个应用可能使用机器学习；查询可能需要特定索引；执行可能最终进入支付系统；而存储则可能根据领域与规模要求完全不同的属性。试图把这些机制全部内置到一个单一环境中，就意味着构建一个不断向“实现任何应用可能需要的任何计算方式”扩张的系统。

这不是 FormaSL 的职责。语言需要规定计算的意义、它接收的区别，以及它的结果必须满足的义务。它不需要成为执行每一种计算的物理机制。一个专用组件完全可以更好地解决某个问题，而不会因此获得重新定义自己所接收契约的权威。

当前架构把这条边界显式表达出来。`.fsl` 声明语义契约，并继续作为它的权威来源；实现属于另一个独立层。实现可以根据具体情况选择适当的机制、资源和策略，只要它满足契约施加的义务。具体执行与存储又是彼此不同的责任。它们可以在同一个运行系统中组合，但并不需要共享身份或语义权威。

因此，我们抵达了“语言作为孤立答案”的边界。FormaSL 让我们能够声明一个语义结构化的世界，并规定在这个世界上进行的不同计算形式。但语言自身的成功也创造了一个架构要求：数据库、推理机制、模型、模拟器、服务和其他能力必须能够实现这些计算，而无需在每个组件内部重新发明语义。

如果意义必须保持稳定，而实现可以变化，那么接下来的问题就不再是“使用什么语言”，而是“什么架构能够让这种分离在计算上持续成立”。
