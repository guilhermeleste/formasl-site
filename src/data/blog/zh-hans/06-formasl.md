如果意义在计算过程中消失，那么即使输入阶段建模得再准确，也没有解决真正的问题。

信息会穿过查询、转换、模型、推理、服务、决策与执行。每经过一步，表示形式都可能变化。危险在于：形式变化的同时，意义也被静默改变。

假设一个风险模型产生了预测。它经过两个服务，进入一条运营规则，最后显示在界面上。如果到终点时，我们已经无法知道它原本是某个模型在特定条件下产生的预测，那么数值可能被完整保存，而意义已经丢失。

假设世界也有同样问题。某个场景中计算出的结果，数值上可能与现实世界中的结果完全相同。如果它与那个假设场景之间的依赖消失，后续系统就无法再区分二者。

Forma 把一种关键属性称为 **Semantic Continuity**：凡是解释结果仍然需要的语义区分，在相关转换之后都必须保持可重建。

“可重建”是关键。

系统不需要把所有东西复制到每个地方。表示可以压缩、索引、投影或转换。真正重要的是，通过直接保存、稳定引用或可追溯关系，让仍然影响意义的信息继续存在。

一条 Claim 仍然可以追溯到它的来源。预测仍然被识别为预测。假设仍然绑定到引入它的场景。决策仍然与它授权的执行保持区分。观察仍然与它观察到的效果保持关联。

这建立了一种不同的正确性标准。

我们不能只问转换是否返回了正确类型，或者 API 是否成功响应。还必须问：契约要求的语义区分，在转换之后是否仍然能够恢复？

当本来应该不同的两种情况变得不可区分，就发生了语义擦除。

这在组合式架构中尤其危险。每个组件单独看都可能技术上正确，但整条链仍然破坏意义。模型输出一个评估，服务把它当建议，另一个服务把建议压成 boolean，最后一个系统又把这个 boolean 当作决策。

技术上没有任何一步“报错”。语义却已经失败。

Semantic Continuity 让不同机制可以继续专业化，而不必在每个系统边界重新制造语义碎片化。

**表示可以变化。意义必须继续可重建。**

当这一点成立，同一个世界就可以穿过多种不同的计算机制，而不失去自己的语义身份。

于是问题从“如何表示意义”进一步变成：我们能直接在意义之上做什么计算？
