今天，应用的许多意义都与实现一起产生。一个表结构会隐含地定义实体是什么，一段条件代码决定规则何时成立，一个服务集中某项政策，一个 API 决定哪些关系能够跨越两个系统之间的边界。

因此，应用对其实现的依赖远比对某个数据库、框架或云平台的依赖更深。真正的锁定，不只是技术锁定，而是意义被隐藏在具体实现中的锁定。

语义计算提出另一种架构。

系统不再让概念和规则散落在实现中，而是显式声明自己所表示的世界：实体、关系、语境、时间、权威、政策以及行动条件。这个定义独立于实现它的具体技术。

依赖方向因此被反转。

过去，我们观察后端行为，才能推断应用意味着什么。现在，后端接收一个已经定义好意义的契约，并负责实现它。

数据库仍然负责存储，服务仍然负责执行，模型仍然负责分析和预测，API 仍然负责连接系统，云仍然负责提供计算资源。但这些组件不再需要成为系统语义的最终来源。

这改变了后端的角色。

**后端不再定义应用，而是实现应用。**

由此产生语义与实现之间的独立性。同一个领域可以由不同技术实现。数据库可以被替换，而关系的意义不需要被重新定义。模型可以变化，而预测不会因此自动变成决策。服务可以重写，而领域规则不必在新服务中重新发明一次。

这种分离也改变了“可移植性”的含义。迁移软件不再只是移动数据或代码，而是能够在基础设施变化时继续保存系统原本的意义。

目标不是消灭实现，而是把实现放回正确的位置。

实现应该可以自由选择机制、优化表示并组合不同技术；契约则保持为判断系统哪些语义属性必须继续成立的基准。

正是这种分离，使“意义作为基础设施”成为可能。

而如果意义拥有了自己的层，它也需要一种自己的声明方式。

我们需要一种能够直接描述世界、关系与规则的语言。

这就是 FormaSL 的起点。
